# 分科六法庫：新增與更新法規的操作指引

這份指引寫給接手的 AI（例如 Claude Code 的 law-library Skill）或你自己。照著做，就能把一部法規轉成 Obsidian 逐條頁面，格式和庫內既有法規一致。開工前請讀完全文。

## 一、成品長什麼樣

- 位置：本庫根目錄的 `分科六法整理/`（`法規庫.py` 預設寫到這裡；要寫到別處，設定環境變數 `LAW_LIBRARY_DIR` 指向你的「分科六法整理」資料夾）。
  - `00-總覽與看板/`：`分科六法總覽.md`（各類別已建法規清單）、`法條整理進度.base`（看板）
  - `01-公法/`、`02-民事法/`、`03-刑事法/`、`04-商事法與智慧財產權法/`、`05-憲法法庭判決及大法官解釋/`
  - 每部法規一個子資料夾，例如 `03-刑事法/中華民國刑法/`，內含：
    - `中華民國刑法.md`：法規總覽，依編章節列出全部條文。由腳本整頁產生，不寫筆記。
    - `中華民國刑法第N條.md`：一條一頁。
- 每條頁面：
  - 屬性區：系統欄位（條名、所屬編章、效力等）加上使用者欄位（`progress` 整理進度、`exams` 考試出現、`tags`、`aliases`、`created`）。
  - 條文區：位於 `%% 條文區開始 ... %%` 和 `%% 條文區結束 %%` 之間，內容如下：
    - 上一條／下一條導覽。
    - 條文原文。引用他條的地方都轉成連結，後面括號附條名。
    - 引用條號範圍時，下方用備註框列出範圍內每一條。
    - 引用外部法規時，下方用收合的備註框附上該條全文。
    - 編註、相關解釋，以及效力異動警示。
  - 六個筆記欄位：法條解析、思考脈絡、實務見解、爭點、近年考試出現、相關考題，另加「相關條文與解釋」。
- 條文區每次執行都會整段重寫，條文區以外的內容腳本絕不改動。

## 二、檔案與工具

全部放在 `tools/`：

| 檔案 | 用途 |
| --- | --- |
| `法規庫.py` | 主程式，子命令 `scan`、`check-ext`、`build`、`verify` |
| `法規登錄.json` | 每部法規一筆：`short` 簡稱、`category` 分類資料夾、`config` 設定檔路徑、選填 `src` 來源檔 |
| `設定/<法規全名>.json` | 該法規的自擬條名、外部引用條文、效力異動、法規名稱對照 |
| `來源/` | 放全國法規資料庫下載的 Word 檔（不會上傳 GitHub） |
| `requirements.txt` | Python 套件：`python-docx`、`PyYAML` |
| `使用指引.md` | 本檔 |

執行環境：Python 3.10 以上（macOS 建議從 python.org 安裝）。第一次使用，在 `tools/` 資料夾安裝套件：

```
python -m pip install -r requirements.txt
```

- 用 `python -m pip`，確保套件裝進執行腳本的同一個 Python。
- `python -I` 不會讀取「使用者層級」的套件（用 `pip install --user` 裝的）。如果執行時出現 `ModuleNotFoundError: No module named 'docx'`，代表套件裝到了使用者層級。改用虛擬環境：在 `tools/` 執行 `python -m venv .venv`，之後一律用 `.venv` 裡的 Python 安裝與執行（Windows 為 `.venv\Scripts\python`，macOS 為 `.venv/bin/python`）。`.venv/` 已列入 `.gitignore`，不會被同步。

注意事項：

- 先切換到 `tools/` 資料夾再執行，指令裡的路徑就能寫相對路徑（例如 `來源/刑事訴訟法.docx`）。
- 一律用 `python -I` 執行（macOS 若只有 `python3`，就寫 `python3 -I`）。`-I` 讓 Python 不讀取目前資料夾的其他模組，比較安全。
- Windows 的 Git Bash 裡，不要把路徑寫成 `/c/...` 傳給 Python，Python 會把它寫到 `C:\c\` 去。要寫絕對路徑時用 `C:/...`。

## 三、來源檔

- 首選：全國法規資料庫（https://law.moj.gov.tw）的法規頁 →「下載」→ Word 格式（.docx），放進 `tools/來源/`。
- 也可以用 md 檔，但必須是 Word 直接轉出的乾淨版：`#` 標記編章條、段落之間空一行。引用標註版或 Obsidian 頁面不能當來源，腳本會擋下來。
- 條文一律來自全國法規資料庫，不可以憑記憶寫條文。

## 四、新增一部法規（標準流程）

以下 `<全名>` 指全國法規資料庫上的正式名稱，例如「訴願法」「中華民國刑法」。

### 步驟 1　登錄

在 `法規登錄.json` 加一筆：

```json
"訴願法": {"short": "訴願法", "category": "01-公法", "config": "設定/訴願法.json", "src": "來源/訴願法.docx"}
```

- `src`（來源檔路徑，相對於 `tools/`）是選填，但建議填。已登錄、有 `src`、但還沒建頁的法規，其他法規引用它時，會直接從來源檔取條名並建立連結，不必附外部條文。所以幾部互相引用的法規要一起建時：先全部登錄並 scan、補好 `labels`，再依序 build，最後全部再 build 一輪，確認「尚無頁面的連結目標」為無。
- `category` 只能是上面五個分類資料夾之一。
- 法規要放哪一類、簡稱要用什麼，使用者有指定就照辦；沒指定就依常見的分科六法分類決定，並在回報時說明。

### 步驟 2　掃描

```
python -I 法規庫.py scan --src "來源/訴願法.docx" --law 訴願法
```

掃描會在 `設定/<全名>.json` 產生草稿，並列出六類待辦。逐項處理如下。

1. **[1] 被引用但沒有官方條名的條文 → 填 `labels`**
   - 讀該條全文後自擬簡短條名，例如 `"222": "加重強制性交罪"`。
   - 只寫名稱本身，不要寫「〔自擬〕」，腳本會自動加上。
   - 有通行學說用語的，優先用學說用語命名，例如「預防性羈押」「準抗告」「公訴優先原則」「告訴主觀不可分」。沒有通行學說用語的，依條文內容或本法其他條文的用語命名。不論哪一種，都只能放在 `labels`，由腳本標「〔自擬〕」，不可以當成官方條名寫進 `caption`。
2. **[2] 無法判定法規名稱的引用**
   - 典型情形：條文寫「陸海空軍刑法第五十四條」，可是「陸海空軍刑法」沒登錄，又剛好以已登錄的「刑法」結尾。只有兩字的名稱（刑法、民法、刑訴……）會做這個前一字檢查；「民事訴訟法」「海商法」等較長名稱不檢查。
   - 處理方式擇一：
     - 在 `law_names` 加對照，例如 `"陸海空軍刑法": "陸海空軍刑法"`。
     - 直接在 `external` 填該條（見下一項），法規名稱就會自動認得。
   - 如果是本法的別稱，例如條文自稱「刑法」，就把它對到本法全名。
3. **[3] 外部法規條文 → 填 `external`**
   - 先判斷被引用的法規是否已在六法庫建頁。已建頁的話，腳本會直接連過去，不需要填。
   - 尚未建頁的話，從全國法規資料庫取得條文（可用 MCP 工具 `mcp-taiwan-legal-db`，或官方網頁 `https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=<pcode>&flno=<條號>`），照這個格式填：

     ```json
     "刑事訴訟法|121-1": {"label": "暫行安置", "draft": true, "pcode": "C0010001",
       "paras": ["第一項全文", "第二項全文", "　　一、第一款（款前加兩個全形空格）"]}
     ```

   - 依官方網頁的分段，一項或一款一個元素。
   - 官方有條名時，`label` 填官方條名、`draft` 設為 `false`；官方沒有條名時自擬，`draft: true`。
   - 填完執行 `python -I 法規庫.py check-ext --law <全名>`，必須每條都顯示「逐段相同」。這一步會連線到全國法規資料庫官網。
   - **先確認條號版本**：被引用的法規如果在本法該條修正之後曾全文修正，條號可能已重排。讀現行條文，對照本法條文寫的罪名或事項，確認仍是同一條。
     - 現行同條號已是別的規定（例如刑訴第 284-1 條引的洗錢防制法第 14 條）：改填 `{"omit": true, "pcode": "...", "note": "說明"}`，頁面只附說明、不附條文，check-ext 會略過。說明要寫依據（修正沿革第幾點）和查核日期。
     - 仍是同一條、只有結構改變：照常填 `paras`，另加 `"note"`，頁面會在條文後附〔說明〕。
   - 列舉多個條號時（「刑法第二百二十一條之強制性交罪、第二百二十二條之……」），腳本會讓後面的條號沿用前一部外部法規，條件是緊接在「、，及或與」之後，中間沒有「本法」或句號。前一部判不出來時，後面列舉的條號也一律報成判不出來，不會退回本法。新法規 scan 後要抽查這類段落有沒有判錯。
   - 以「條文」結尾的名稱（例如「憲法增修條文」）也當作法規名稱。已登錄法規的其他寫法，要在 `law_names` 加別名，例如憲訴法設定 `"憲法增修條文": "中華民國憲法增修條文"`。
4. **[4] 外部法規的條號範圍** → 填 `ext_ranges`，沒填會擋住 build。
   - 鍵為「法規|起-迄」，值為範圍內實際存在的條號清單（含之一條），依官網全文頁的條文清單決定，不可以自己推算。例如 `"兒童及少年性剝削防制條例|32-35": ["32", "33", "34", "35"]`。清單內每一條都要在 `external` 填好並過 check-ext；該法規已建頁的話，會改成一個範圍備註框，逐條連結過去。
   - 引用的是舊版條號時，填 `{"omit": true, "note": "…"}`，兩端條文照 `omit` 方式附說明。
5. **[5] 修正沿革裡的效力異動 → 填 `status`**
   - 只採修正沿革或官方資料明文記載的內容，例如：

     ```json
     "140": {"status": "部分失效", "note": "113年憲判字第5號判決宣示……（依本檔修正沿革第54點）", "rulings": ["113年憲判字第5號"]}
     ```

   - `status` 只用「部分失效」「失效」這類明載的狀態。不要自己推論失效範圍；不確定就不填，讓頁面維持「現行」。
   - 憲法依增修條文標註時，狀態照增修條文的字面用語分五種：「停止適用」、「部分停止適用」、「不適用」、「部分不適用」（只排除某些有關規定或某個範圍）、「不受其限制」／「部分不受其限制」（只排除某項某款）。增修條文寫「適用」或「除依……之規定外」的條文不標註。`note` 要連到增修條文的頁面（`[[中華民國憲法增修條文第N條|增修條文第N條第M項]]`），並附該項原文，原文由腳本從來源檔取出，不手抄。增修條文要先建頁，再重跑憲法。
6. **[6] 附編註的條文**：腳本會自動抽出釋字號、憲判字號，並建立連結，不需要處理。

處理完再跑一次 `scan`，[1] 到 [4] 都要是空的。

### 步驟 3　試跑

```
python -I 法規庫.py build --src "來源/訴願法.docx" --law 訴願法 --dry-run "../../試跑暫存"
```

- `../../試跑暫存` 位於本庫資料夾**之外**（本庫的上一層）。不要把試跑輸出寫進本庫，否則 Obsidian 會出現重複頁面，Git 插件也會把它同步上去。
- 結尾的核對必須是「問題 0 項」。
- 抽看 3 到 5 頁：有條號範圍的、有外部引用的、有編註的、已刪除的、第一條和最後一條。
- 試跑結束後，`試跑暫存` 資料夾可以自行刪除。

### 步驟 4　正式產生

```
python -I 法規庫.py build --src "來源/訴願法.docx" --law 訴願法
```

腳本會一併做這些事：

- 寫入分類資料夾。
- 產生法規總覽。
- 在 `分科六法總覽.md` 的類別列加上本法連結。
- 自動核對三件事：條文還原和來源逐條相同、屬性區 YAML 可解析、章節錨點都存在。

### 步驟 5　回報使用者

回報內容要包括：

- 建立的位置。
- 條數，以及新建、更新的數量。
- 引用統計。
- 核對結果。
- 自擬條名清單：哪幾條、名稱是什麼。
- 外部條文的比對結果。
- 尚無頁面的連結目標，例如釋字、憲判、其他法規。
- 還沒處理的事項。

## 五、修法後更新

1. 下載新版 Word 檔，放進 `tools/來源/`。
2. 跑 `scan`。新增的條文如果被引用又沒有條名，補進 `labels`。
3. 跑 `build`。
   - 已有頁面只更新條文區和系統欄位，使用者筆記、`progress`、`exams`、自訂屬性、自訂別名都會保留。
   - 新條文會建立新頁面。
   - 已不存在的條文，頁面不會刪除，報告會列在「新版法規已無、但資料夾裡還有的頁面」，交給使用者決定。
4. 頁面如果沒有條文區標記（例如使用者手動建立的頁面），腳本會略過不碰，並在報告中列出數量。
5. 新增或更新一部法規後，對其他已建的法規各跑一次 dry-run，確認「未變」。新登錄的法規名可能改變其他法規的引用判定。

## 六、硬規則

- 不可以憑記憶寫條文。條文只能來自全國法規資料庫的檔案或網頁，外部條文要過 `check-ext`。
- 自擬的條名一定要帶「〔自擬〕」標記，而且不能寫進 `caption` 欄位，只能放在 `caption_draft` 和引用旁的括號。
- 不刪除任何頁面，也不整頁重建已有筆記的頁面。只能用 `build`，靠條文區標記來更新。
- 不修改條文區以外的內容。要改版型時，先改 `法規庫.py` 再重跑，不要手動逐頁改。
- 效力狀態只寫明文記載的內容。「已」「尚未」「目前」這類狀態句要附依據和查核日期。
- 寫檔後要確認實際位置和檔數，例如腳本輸出的「輸出位置」那一行。
